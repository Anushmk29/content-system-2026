# System audit — 2026-10

How the content system works today, before the 2026-10 improvements. Covers requirements 1, 2, 4, 7, 8 and 11 of the improvement list. Paths are relative to the repo root; `src/` means `content-pipeline/src/`.

## 1. Jev integration

**Status: wired up and called, but only advisory.**

- Adapter: `src/adapters/jev.ts`. `POST https://openrouter.ai/api/alpha/decisions`, model `typesafe/jev-1.13` (pinned), same key as the LLM (`CONTENT_OPENROUTER_API_KEY`).
- Modes (`CONTENT_JEV_MODE`): `off`, `shadow`, `primary`. With an OpenRouter key and no mode set it defaults to **shadow**: Jev is called and paid for on every decision, but the LLM answer is the one used.
- Called from:
  - `src/modules/decide.ts:33` — topic scoring and QC risk signals.
  - `src/services/decode-service.ts:355` — `judgePosts`, judging competitor posts (Jev only).
  - `src/services/dataset-service.ts:147` — answering seeded practice examples.
- Response: `{model, answers, usage.cost}` parsed in `jev.ts`; mapped by `fromJev()` per task in `src/modules/decision-tasks.ts`. Cost logged to `content.cost_events`.

**Problems**

| # | Problem | Where | Effect |
|---|---|---|---|
| 1 | `CONTENT_DECISION_MODEL` sends its model id to the chat endpoint. The comment suggests a Jev id, but Jev is non-generative. Rows are logged as `source='claude'` regardless. | `decide.ts:51-57` | If set to a Jev id: failed or unparseable decisions, and mislabelled training rows. |
| 2 | `minConfidence` gives a confidence of 0 to any score/choice answer without a `confidence` field. | `decision-tasks.ts:91-95` | In primary mode, Jev would never be trusted on topic scores if the API omits that field. |
| 3 | Shadow mode runs `Promise.all([llm, jev])`. | `decide.ts:55` | If the LLM fails, the finished Jev answer is never logged — training rows lost. |
| 4 | Network errors are not retried (only HTTP 429/5xx). Errors are swallowed to `null` + a warning. | `jev.ts:105-112`, `decide.ts:36`, `decode-service.ts:367`, `dataset-service.ts:153` | Transient failures silently drop Jev answers. |
| 5 | Jev question wording must be kept in sync with the LLM prompts by hand. | `decision-tasks.ts:5-6` | Shadow comparison stops being fair if they drift. |

No missing-env or wrong-endpoint bug was found.

**Outbound hosts**

| Host | Used for | Where |
|---|---|---|

| `api.anthropic.com` | LLM fallback | `adapters/claude.ts` |

| `www.googleapis.com` | YouTube Data API | `adapters/youtube.ts` |
| `api.search.tinyfish.ai`, `api.fetch.tinyfish.ai` | News search, watched pages | `adapters/tinyfish.ts` |
| `api.x.com` | X recent search | `modules/market-signals.module.ts` |
| `www.reddit.com` | Subreddit / search feeds | `modules/market-signals.module.ts` |
| `fonts.googleapis.com` (+ `fonts.gstatic.com`) | Brand fonts | `src/fonts.ts`, `ui/BrandKit.tsx` |
| Postiz (`CONTENT_POSTIZ_API_URL`) | Scheduling, post stats | `adapters/postiz.ts` |
| Env-configured RSS / watch URLs | Market signals | `market-signals.module.ts` |

The Next.js app only calls its own `/content/api/*` routes.

**What is solid:** no `NEXT_PUBLIC_` secrets; keys read server-side only. HMAC-signed session cookie, timing-safe comparisons, `httpOnly`. Spoofed role headers are stripped in `middleware.ts`. Every write route goes through `handle()`/`denied()`. No server-side fetch of user-supplied URLs (no SSRF found). Uploads are size-capped and type-checked by magic bytes.

**Weak points**

| Severity | Issue | Where |
|---|---|---|
| High | No rate limiting: login password and `x-content-secret` can be brute-forced; LLM/Apify-spending routes are unthrottled. | all routes |
| High | Cron secret and the client login password are the same value. | `CONTENT_RUN_SECRET`, `auth.ts` |
| Medium | `handle()` returns raw exception text (incl. DB errors) to the client; `fetchJson` echoes 300 chars of upstream bodies. | `app/content/api/guard.ts:37`, `adapters/adapter.ts:16` |
| Medium | No CSRF Origin check; only `SameSite=Lax`. | `middleware.ts` |
| Medium | DB TLS defaults to `rejectUnauthorized: false`. | `src/db/client.ts:42` |
| Low | No security headers (CSP, frame options). | `next.config.mjs` |
| Low | Health details and adapter errors visible to the client role. | `api/health`, `today-service.ts:110-128` |
| Low | Asset upload reads any number of files into memory before the service caps them. | `api/items/[id]/asset/route.ts:23` |
| Low | SVG logos accepted and rasterised by sharp/librsvg. | `ui/BrandKit.tsx:248`, `brand-service.ts:205` |
| Low | Font `name`-table parser reads offsets without bounds checks (fails as a 400). | `src/fonts.ts:17-35` |

## 7. What a change request does

1. UI requires a note for "Request changes" or "Reject" (`app/content/ui/editors.tsx:10-25`).
2. `PATCH /content/api/approvals/[id]` → `applyApprovalDecision` (`src/services/approval-service.ts:23`).
3. The item moves `needs_approval|approved → draft`, `approval_status = 'changes_requested'`, and a row with the note is added to `content.approvals`.
4. **No model is called. The note is never sent to any prompt.**
5. On the next pipeline run, `qc_gate` re-runs the QC decision on the **unchanged** text and sends the item straight back to `needs_approval`.

So unless someone edits the copy by hand, the same post comes back. Nothing upstream (research, scoring, drafting) re-runs.

The only free-text-note → regeneration path in the system is in Styles (`remakeTemplate` → `FIX_PROMPT`, `style-service.ts:733-756`).

## 8. How feedback is stored and whether the system learns

| Store | Content | Linked to | Used later? |
|---|---|---|---|
| `content.approvals` | decision, lane, note, time; `decided_by` is always `'dashboard'` | the post | Note is only displayed. Dataset export uses the approve/reject flag only; `changes_requested` and notes are ignored. |
| `content.decisions` | every model answer + exact input text, source (claude/jev/rules/human), confidence | task + subject | Exported as weighted JSONL for **offline** training. Not read back into prompts. |
| `v_hook_pattern_weights` (view) | hook pattern performance from real post metrics | hook pattern | **Yes** — feeds draft prompts and hook ranking. |

**There is no LSTM or other persistent learning model.** The only live loop is hook-pattern weights from real performance. Human feedback (notes, edits) does not influence future generations.

## 11. How market research decides what to fetch

**Market Signals** (`src/modules/market-signals.module.ts`) is configured only by environment variables:

| Source | Env var | Rule |
|---|---|---|
| RSS/Atom | `CONTENT_MARKET_FEEDS` | Latest entries; optional `channel=` prefix |
| Reddit | `CONTENT_REDDIT_QUERIES` | `r/name` → top posts this week; other text → search, newest, past week |
| X | `CONTENT_X_QUERIES` | Recent search, `-is:retweet -is:reply lang:en`, by relevancy |
| TinyFish news | `CONTENT_TINYFISH_QUERIES` | News from the last 7 days |
| TinyFish watch | `CONTENT_TINYFISH_WATCH` | A page becomes a signal only when its content hash changes |

- Max 10 items per source per run; dedupe by `source_url`.
- **No include/exclude filter.** The only filter is downstream: topics scoring under 10 (`drop` band) fall away.
- There is no list of people to follow here.

**Decode** (competitor research, `src/services/decode-service.ts`):

- **Accounts:** whatever the user adds to `content.competitors` (handles per platform) plus the brand's own accounts.
- **Window:** lookback 7–365 days (default 90), 5–500 posts (default 10; 30 for own accounts).
- **Scrapers:** Apify actors per platform; YouTube via the Data API.
- **Ranking:** "x their usual" — each post's views/reactions vs that account's median.
- **Judging:** Jev (lane, ICP fit, proof, replicability, sponsored).
- **Hunt score:** `100·√(demand·fit)`; posts flagged paid when engagement < 0.2%, or < 0.6% while 3x+ breakout, or Jev says sponsored.

**Docs that were not wired in:** the subreddit list in `prompts/platform-rules.md` and every file in the root `prompts/` folder were documentation only (removed in the 2026-10 cleanup; still in git history). Live prompts are in `src/prompts/brand-brain.ts`, with the brand from `content.brand_kit`.
